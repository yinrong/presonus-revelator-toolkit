Why It Breaks (The Hidden Windows Kernel Trap)

Android requires Multi Mode (VID_194F&PID_0D09, 3 independent 2-channel stereo UAC2 interfaces). Windows Universal Control uses Single Mode (PID_0D08, 6-channel)—which crashes Android USB Audio HAL/DSP (transfer failed, DSP SSR, AudioRecord read -> buffer is mute).

Worse, PreSonus's Windows driver (paedspusb.inf → PaeDSPUSB.sys) writes a kernel registry key Config\RestartDeviceRequest (RequestType=64, RequestCode=66 / 0x42, RequestValue=0) on PID_0D09. Within 1 second of plugging a Multi-Mode Revelator into Windows, the driver silently reprograms the mic back to Single Mode—even without opening Universal Control.

3-Step Fix on Windows (No Mac Required)

git clone https://github.com/yinrong/presonus-revelator-toolkit.git
cd presonus-revelator-toolkit

# 1. Diagnose USB mode (PID_0D08 vs PID_0D09) and active RestartDeviceRequest traps
python scripts/revelator_mode.py diag

# 2. Disarm the PaeDSPUSB.sys auto-revert registry key (backs up JSON first)
python scripts/revelator_mode.py disarm --elevate --backup trap-backup.json

# 3. Switch to Android Multi Mode (PID_0D09) and verify 10 seconds with zero revert
python scripts/revelator_mode.py switch multi

Or simply double-click fix_android_mode.bat on Windows.
